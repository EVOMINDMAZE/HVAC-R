## 2024-05-24 - Fail-Secure JWT Authentication Fallback
**Vulnerability:** The application was falling back to an insecure, hardcoded default JWT secret ("fallback-secret-change-in-production") in production when `JWT_SECRET` and `SUPABASE_JWT_SECRET` environment variables were not set. This allows arbitrary actors to forge JWT tokens and gain full unauthorized access.
**Learning:** Security-critical configuration failures must lead to a complete operational halt rather than a degraded, insecure operational state. Falling back to an insecure state provides a false sense of functionality while leaving the application highly vulnerable. This is the essence of a "fail-secure" policy.
**Prevention:** Implement checks that strictly require secure secrets in production environments. If a secret is missing or matching an insecure placeholder (e.g. "your_super_secret_jwt_key_change_in_production"), the app should throw a critical error or return a 500 status code, actively preventing insecure authentication flow.
