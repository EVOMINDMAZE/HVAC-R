## 2025-02-28 - [CRITICAL] Insecure JWT Secret Fallback in Production
**Vulnerability:** The `authenticateSupabaseToken` middleware used a fallback hardcoded secret (`"fallback-secret-change-in-production"`) to verify JWT tokens if the environment variable (`JWT_SECRET` or `SUPABASE_JWT_SECRET`) was missing. This would allow attackers to forge tokens and take over accounts if the server was mistakenly deployed to production without the secret configured.
**Learning:** Hardcoded fallbacks for critical secrets (like JWT keys) provide a false sense of security. The application appeared to work fine, hiding the missing configuration, but was completely vulnerable in production.
**Prevention:** Implement a strict fail-secure policy for critical configuration. In production environments (`NODE_ENV === "production"`), missing secrets must cause the application to fail to start or throw fatal errors (e.g., return `500 Internal server configuration error`), rather than silently falling back to insecure defaults.
