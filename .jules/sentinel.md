## 2024-03-14 - [CRITICAL] Insecure Default JWT Secret
**Vulnerability:** In production environments, if the `JWT_SECRET` and `SUPABASE_JWT_SECRET` environment variables were missing or left to insecure defaults, the authentication middleware in `server/utils/supabaseAuth.ts` fell back to a hardcoded string ("fallback-secret-change-in-production") or a weak default ("your_super_secret_jwt_key_change_in_production") to verify JWTs. This violated the application's fail-secure policy for critical configuration.
**Learning:** Development defaults and fallback strings should never be permitted in production for critical cryptographic operations like JWT signature verification. The system should "fail closed" rather than "fail open" (or use weak cryptography).
**Prevention:** Implement strict assertions in authentication middleware that check `process.env.NODE_ENV === "production"` and explicitly throw fatal errors or return 500 status codes if cryptographic secrets match known default/fallback strings or are missing.
